## Что нужно сделать на GitHub

### Шаг 1: Загрузите изменения в репозиторий

Загрузите следующие файлы в ваш репозиторий `smetchiknn-bit/Stiker1C`:

1. **`vite.config.js`** — обновлённый файл с настройкой `base`
2. **`.github/workflows/deploy.yml`** — новый файл для автоматического деплоя
3. **`index.html`** — обновлённый путь к favicon

### Шаг 2: Настройте GitHub Pages

1. Откройте ваш репозиторий на GitHub: https://github.com/smetchiknn-bit/Stiker1C
2. Перейдите в **Settings** (Настройки)
3. В левом меню выберите **Pages**
4. В разделе **Build and deployment**:
   - **Source**: выберите **GitHub Actions**
   - Это активирует автоматический деплой через workflow

### Шаг 3: Дождитесь первого деплоя

После загрузки файлов:
1. Перейдите на вкладку **Actions** в вашем репозитории
2. Вы должны увидеть запущенный workflow "Deploy to GitHub Pages"
3. Дождитесь успешного завершения (обычно 2-3 минуты)
4. После успешного деплоя ваш сайт будет доступен по адресу:
   **https://smetchiknn-bit.github.io/Stiker1C/**

## Как это работает

### Автоматический деплой

Workflow `.github/workflows/deploy.yml` автоматически:
- Запускается при каждом push в ветку `main`
- Устанавливает зависимости (`npm ci`)
- Собирает проект (`npm run build`)
- Загружает содержимое папки `dist` на GitHub Pages
- Деплоит сайт

### Ручной запуск деплоя

Если нужно запустить деплой вручную:
1. Перейдите на вкладку **Actions**
2. Выберите workflow "Deploy to GitHub Pages"
3. Нажмите **Run workflow**
4. Выберите ветку `main` и нажмите **Run workflow**

## Возможные проблемы

### Проблема: Страница не загружается (404)

**Решение:**
- Убедитесь, что в Settings → Pages выбран Source: **GitHub Actions**
- Проверьте, что workflow успешно завершился на вкладке Actions
- Подождите 5-10 минут после первого деплоя (GitHub Pages кэширует)

### Проблема: Страница загружается, но без стилей (белый экран)

**Решение:**
- Проверьте, что в `vite.config.js` есть строка `base: "/Stiker1C/"`
- Убедитесь, что имя репозитория точно `Stiker1C` (с учётом регистра)
- Проверьте консоль браузера (F12) на ошибки загрузки ресурсов

### Проблема: Логотипы не загружаются

**Решение:**
- Убедитесь, что файлы `logo.png`, `logo2.png`, `FSKicon.png` находятся в папке `public/` в репозитории
- Проверьте, что файлы закоммичены и запушены

### Проблема: Workflow не запускается

**Решение:**
- Убедитесь, что файл `.github/workflows/deploy.yml` находится в корне репозитория
- Проверьте, что вы запушили изменения в ветку `main`
- Проверьте вкладку Actions для просмотра логов ошибок

## Преимущества GitHub Pages

✅ **Бесплатно** — GitHub Pages полностью бесплатен для публичных репозиториев
✅ **Автоматический деплой** — каждый push в `main` автоматически деплоит сайт
✅ **Интеграция с GitHub** — не нужен отдельный сервис, всё в одном месте
✅ **Быстрый хостинг** — GitHub Pages использует CDN для быстрой доставки контента
✅ **SSL/TLS** — автоматический HTTPS для вашего сайта

## Дополнительные настройки (опционально)

### Кастомный домен

Если хотите использовать свой домен (например, `stiker1c.example.com`):

1. В Settings → Pages укажите ваш домен
2. Добавьте CNAME запись у вашего регистратора домена
3. Создайте файл `CNAME` в корне репозитория с именем домена

### Защита от прямого доступа к файлам

Если нужно запретить прямой доступ к файлам в `public/`, можно добавить `.htaccess` (но GitHub Pages не поддерживает серверные конфигурации, так что это не применимо).

3. Убедитесь, что все файлы загружены в репозиторий
4. Проверьте настройки GitHub Pages в Settings
